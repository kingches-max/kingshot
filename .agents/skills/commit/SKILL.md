# 🚀 Git 커밋 & 푸시 원스톱 스킬 (`commit`)

유저가 커밋 및 푸시를 요청하면 아래 **4단계**를 순서대로 실행한다.

---

## Step 1. 변경 상태 사전 점검
* 현재 워크스페이스에서 `git status -sb` 및 `git diff --stat`을 실행해 변경·신규·삭제 파일을 확인한다.
* 변경 사항이 전혀 없으면 커밋하지 않고 `"변경 사항 없음"`을 보고하고 종료한다.
* 민감 파일(`.env`, 인증키 등)이나 의도치 않은 임시 파일이 섞여 있으면 스테이징 전 유저에게 확인한다.

## Step 2. 커밋 메시지 작성 규칙
* 변경 내용의 핵심을 1줄 한국어 Conventional Commit 형식으로 작성한다:
  * 문서·전략 갱신: `docs: <핵심 변경 요약>`
  * 스킬·설정 추가/수정: `chore: <핵심 변경 요약>`
  * 복합 변경 시 주 목적 접두사 사용 (예: `docs: ... 및 commit 스킬 추가`)

## Step 3. 스테이징 · 커밋 · 푸시 실행
* 현재 브랜치(`git branch --show-current`)를 확인한 뒤 아래를 일괄 실행한다:
  ```bash
  git add -A && git commit -m "<커밋 메시지>" && git push origin <브랜치>
  ```
* 푸시 실패(원격 선행 커밋, 권한 오류 등) 시 임의로 강제 푸시(`--force`)하지 않고 오류 원인을 보고한다.

## Step 4. 결과 보고 양식 (간결 단답)
* **커밋**: `<단축 해시>` (`<브랜치> -> origin/<브랜치>`)
* **메시지**: `<커밋 메시지>`
* **반영 파일**: 변경 파일 수 및 주요 파일 클릭 링크(`file://`)
